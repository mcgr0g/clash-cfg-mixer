# AI Collaboration & Unified Testing Guidelines

This document establishes the precise interaction protocols and mandatory local/CI testing matrix boundaries for AI entities (such as `oh-my-pi`).

## 1. Language Protocols
* **User/Chat Interactions**: Always respond to the user in the exact language they used to initiate the prompt or message (e.g., if the user writes in Russian, the conversational response must be in Russian).
* **Repository Content**: All code, script syntax, structural schemas, inline comments, commit messages, and documentation files MUST be strictly written in English.
* **AI AI Disclaimer**: If an automated agent autonomously opens an **Issue** or **Pull Request**, it MUST embed the following notice string exactly in the middle section of the text:
  > *This message was automatically generated by an AI assistant; minor inaccuracies or contextual edge cases may occur.*

## 2. Unified Testing Framework (Local & CI Execution)
The repository enforces a single, unified integration testing routine that can be executed **both locally** by a developer/agent and **automatically on GitHub Actions CI**.

* **Test Data Folder**: All static baselines and expected outputs must reside under the `tests/fixtures/` directory:
  * `tests/fixtures/input/` — Mock source configs (`cfg.mih.uni.yml`, etc.)
  * `tests/fixtures/expected/` — Expected compiled files (`config-nas.yml`, `config-cell.yml`) used for `diff` assertions, plus normalized runtime-dump ground truth (`general-nas.yml`, `general-cell.yml`) for the mihomo API comparison.

### Execution Routine For Agents & CI Run:
To run the full cycle validation, execute the following script steps locally or let the CI handle it:

```bash
# Single entry point: builds, boots the isolated stack, runs mix.sh directly,
# triggers the webhook, verifies compiled outputs and live mihomo runtime state, tears down.
mise run test
# Granular isolated steps for troubleshooting (DAG in mise.toml):
#   test:build  test:up-mixer  test:mix-direct  test:up-proxies
#   test:trigger  test:verify-mix-{nas,cell}  test:verify-api-{nas,cell}
```

Token note: the webhook token comes from the `WEBHOOK_SECRET_TOKEN` env var (mise `[env]`, overridable via `.env`), no longer hardcoded in examples.
